## 2. 指标身份规则（用户反复确认，最高优先）

1. **指标身份必须从一开始就准确**：不能反复把“旧身份没对齐”当成允许数据串组的理由；同一医学指标跨医院统一归类，**不同测量身份绝对不能合并**。内部 ID 必须稳定，中文名称变化不得生成新身份。
2. **代码、完整中文名称、别名、单位、参考范围、检查类型，以及需要时的项目顺序/位置共同辅助核对**；显式准确代码是粘贴固定格式的身份依据，不能以部分前缀、仅中文近似或共享缩写进行猜测。身份冲突时必须指出问题、让用户核对，不自动替换单位或猜另一身份。
3. **CV 与 SD 完全独立**：
   - `RDW-CV`（红细胞分布宽度CV）≠ `RDW-SD`（红细胞分布宽度SD）；
   - `PDW-CV`（血小板分布宽度CV）≠ `PDW-SD`（血小板分布宽度SD），这条是用户**早已多次明确强调**的规则，不是 2026-10-16 才提出的新增需求；
   - `%` 与 `fL` 对应不同测量属性时是**身份问题，不是“单位显示改一下”的问题**。代码与名称、单位不一致，不能错误入库；也不能仅看单位而静默改变用户已确认的身份。
   - 原始无 CV/SD 信息的 `RDW`/`PDW` 不可未经确认自动归为某种类型。
4. **绝对计数与百分比必须独立**：中性粒、淋巴、单核、嗜酸、嗜碱 `#`/`%` 各为不同身份；有核红细胞绝对计数 `NRBC#` 和百分比 `NRBC%` 也独立；不能将结果、参考范围或趋势混用。
5. **独立的生化指标及比值不能串值**：
   - `AST` 是谷草，`ALT` 是谷丙；
   - `AST` 与 `AST/ALT` 分开；`AST/ALT` 与 `ALT/AST` **方向不同、不得合并或倒置**；
   - `CKMB` 与 `CKMB/CK` 分开，`CKMB/CK` 的中文名必须完整；
   - `PCT`（血小板压积）与 `PCTIN`（降钙素原）不能同码混淆。
6. **所有普通界面的指标名称使用完整中文名称**，不要在项目名前面显示英文缩写；英文代码用于内部识别（若中文名称本身含英文则保留），标题不随意加英文括号。对尚未确认的 CKMB/CK、CK 等中文身份不得编造名称以蒙混保存。
7. 统一词典应支持医院之间的**同义词/别名**精确对齐及冲突校验；用户维护的别名应持久化，不能每次升级或重启丢失。未知指标要能识别为“待核对”并经用户确认后保存；**不得因为词典不包含新项目就整份拒绝导入**；未经确认不得自动纳入标准词典或污染已确认模板。
8. 词典按检测类型扩展，**不要假设固定最大指标数**；每个新增指标都须核查真实医学身份，不只是添加近义名称。

## 3. 当前报告输入路径与固定粘贴格式（以较新指令为准）

1. 用户 2026-10-16 再次明确：**检查报告数据导入模块不使用 OCR**，不是“暂缓优化”或“次要入口”。检查报告数据由用户看原始照片后，按固定格式**人工整理后粘贴导入**，或手工录入。报告首页不得提供拍照识别报告、相册识别报告入口，报告导入实现不得调用文字识别器。**只有“图片资料”模块保留 OCR 功能**，不得一起删掉、禁用或停止维护。
2. 粘贴格式**不得改动**：
   ```text
   霞浦县中医院
   血常规
   2026-10-06
   WBC 白细胞 8.42 10^9/L 3.5-9.5
   ```
   第一行医院，第二行检查类型，第三行日期 `YYYY-MM-DD`，随后逐行 `项目代码 中文名称 结果 [单位] [参考范围]`。也适用生化、其他检查类型。**禁止新增英文缩写前置显示、不改变输入格式。**
3. 粘贴首列代码必须按**完整代码身份精确绑定**，尤其 `AST` / `AST/ALT`、`ALT/AST`、`NEUT#`/`NEUT%` 等；名称、单位及参考范围发生矛盾时提示核对；**报告粘贴链路与 OCR 误识别纠正逻辑隔离**，不得互相破坏。
4. 现在新报告不再依赖医院的旧 `current` 模板决定标准身份；**旧模板保存为历史兼容/只读资料**。注：2026-10-06 用户曾明确要求粘贴按医院+类型 `current` 模板精确映射，属早期阶段；2026-10-13/14 统一词典新报告规则已调整此依赖，**禁止倒退回旧模板作为新报告唯一身份依据**。
5. 旧报告中的 `rawOcr`、原图和图片关联属于历史数据兼容字段，必须原样保留；保留这些历史字段不代表允许重新启用报告数据 OCR，也不得在打开、搜索、升级或编辑时重新识别旧报告。
6. 普通 `PDW` 冻结的是**自动归类**：来源写 `PDW` 时保留 `PDW` 身份、原始 `%` 或 `fL` 单位并允许用户核对保存，不得仅凭单位改成 `PDW-CV` 或 `PDW-SD`。只有来源名称明确写出 CV/SD 却仍绑定普通 `PDW` 时才作为身份冲突拦截。
5. **本次实际检测几项就只生成、核对、保存几项**；未检测的指标不新增，不补 0，不复制之前值，不把参考范围下限当结果。新增/未确认的指标核对后可保存，不能因为模板缺少字段直接锁死整份报告。
6. 报告核对页应显示、允许修改、删除每个输入项；其他涉及数值/数据的输入位置也应有修改与删除能力；取消编辑不应误删既存记录。
7. 医院、检查类型、报告日期、指标结果、来源原图应保持对应；不要把患者**出生日期误识别成报告日期**。
8. 报告中文名称、值、单位和参考范围必须以来源报告为准，存在冲突时保持“待核对”而非假定正确；医院不同参考范围不能彼此覆盖。

## 4. 数据显示、精度与单位（长期有效）

1. **`displayUnit` 与内部 `canonicalUnit` 分离**。UI 展示忠实使用来源/已确认显示单位；例如 `10^9/L`、`10^12/L`、`g/L`、`fL`、`%`、`pg`；**禁止私自加 `×`**。
2. 结果必须保留原始小数位，不把 `32.30` 改为 `32.3`、`0.00` 改为 `0.0`、`0.000` 改为 `0`。原参考范围上/下限与检验单位同步保存。
3. 显示层级固定：**结果最大最醒目 > 单位次级灰色 > 参考范围更弱**；结果、单位和参考范围分别使用控件，不能互相覆盖、拼接成错误数值。
4. **参考范围属于每一次真实报告**，不是跨医院统一的通用正常区间。出现单位/身份歧义不可通过换算或覆盖来掩盖；如确需内部标准换算，数值与区间上下限必须一起转换，原始值保持不变。
5. 对同一医院+同一检查类型曾手工确认的模板字段，不得让机器识别生成“乱码新项目”（例如把单位/代码拼进中文名）；新增项目先“待核对”，是否正式加入模板要另行确认。

## 2026-10-16 词典精准定位补充约束
- **必须精准定位，不允许“相似医学术语/近似 LOINC 编码”被当作确认通过**。LOINC 如有不同测量属性（质量浓度/物质浓度、活性/质量浓度）、计算法/直接法或 FEU/DDU，必须精确区分；不能靠同名、单位可换算或别名类似擅自绑定。
- **尿素与尿素氮**：测量对象相关，但一个是尿素整体、一个是尿素中的氮对应计量；原报告身份、数值、原单位保留。不能将尿素氮结果直接作为尿素浓度；**词典身份识别和自动归类时禁止尿素/尿素氮跨身份换算或合并；不需要、也不应以换算作为两者对齐的规划。**
- **LDL-C 直接法与计算法**：同一类胆固醇测量对象，结果取得方式不同；精确 LOINC 映射需按测量属性和方式定位，来源无明示时不能猜；医院只是来源标签。
- **CK-MB**：酶活性浓度与质量浓度分别判别，不能只绑定一个模糊 CKMB 测量术语。
- **D-二聚体**：FEU 与 DDU 必须区分，不可按相同数字视作同一量，不可自行套一个固定比例重写历史值。
- **核验状态严格区分**：“精准匹配并有官方来源”“只有条件候选”“未找到可靠对应”三种。后两种不得计作已精确核验。院方/机器认证不属于任务。
