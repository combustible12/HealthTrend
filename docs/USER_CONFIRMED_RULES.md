## 0. 最新明确纠正：医院只是来源标签（2026-10-16，最高优先级）

1. **医学指标先按统一身份收录进全局词典/指标池，数据完成识别和归类后，医院名称才作为便于查看、筛选记录的来源标签添加。**
2. **医院不参与词典身份匹配、标准身份定义、别名归属、同指标合并判定或词典规划。** 同一个指标不因医院不同生成新 ID、单独词典或强制模板。

4. 医院名称在报告中仍照常保存，供历史检索与来源展示；**来源标签不得反向决定指标身份**。历史人工确认模板仅作兼容保留，不作为新报告词典条件。
5. 如旧核验规范、审计台账、开发清单出现“医院/仪器/方法认证 0/112”“必须核对具体设备才能算通过”等规划，**一律废止**。不因医院/仪器认证未做而降低医学词典复审进度，也不得继续向用户汇报该项。
6. 医学概念和单位测量属性仍要正确：不是忽略 CV/SD 等差异，也不是允许错误单位硬套身份。核查的是**指标本身**，不是哪家医院用什么机器。

## 2. 指标身份规则（用户反复确认，最高优先）

1. **指标身份必须从一开始就准确**：不能反复把“旧身份没对齐”当成允许数据串组的理由；同一医学指标跨医院统一归类，**不同测量身份绝对不能合并**。内部 ID 必须稳定，中文名称变化不得生成新身份。
2. **代码、完整中文名称、别名、单位、参考范围、检查类型，以及需要时的项目顺序/位置共同辅助核对**；显式准确代码是粘贴固定格式的身份依据，不能以部分前缀、仅中文近似或共享缩写进行猜测。身份冲突时必须指出问题、让用户核对，不自动替换单位或猜另一身份。
3. **CV 与 SD 完全独立**：
   - `RDW-CV`（红细胞分布宽度CV）≠ `RDW-SD`（红细胞分布宽度SD）；
   - `PDW-CV`（血小板分布宽度CV）≠ `PDW-SD`（血小板分布宽度SD），这条是用户**早已多次明确强调**的规则，不是 2026-10-16 才提出的新增需求；
   - `%` 与 `fL` 对应不同测量属性时是**身份问题，不是“单位显示改一下”的问题**。代码与名称、单位不一致，不能错误入库；也不能仅看单位而静默改变用户已确认的身份。
   - 原始无 CV/SD 信息的 `RDW`/`PDW` 不可未经确认自动归为某种类型。
4. **绝对计数与百分比必须独立**：中性粒、淋巴、单核、嗜酸、嗜碱 `#`/`%` 各为不同身份；有核红细胞绝对计数 `NRBC#` 和百分比 `NRBC%` 也独立；不能将结果、参考范围或趋势混用。
5. **独立的生化指标及比值不能串值**：
   - `AST` 是谷草，`ALT` 是谷丙；
   - `AST` 与 `AST/ALT` 分开；`AST/ALT` 与 `ALT/AST` **方向不同、不得合并或倒置**；
   - `CKMB` 与 `CKMB/CK` 分开，`CKMB/CK` 的中文名必须完整；
   - `PCT`（血小板压积）与 `PCTIN`（降钙素原）不能同码混淆。
6. **所有普通界面的指标名称使用完整中文名称**，不要在项目名前面显示英文缩写；英文代码用于内部识别（若中文名称本身含英文则保留），标题不随意加英文括号。对尚未确认的 CKMB/CK、CK 等中文身份不得编造名称以蒙混保存。
7. 统一词典应支持医院之间的**同义词/别名**精确对齐及冲突校验；用户维护的别名应持久化，不能每次升级或重启丢失。未知指标要能识别为“待核对”并经用户确认后保存；**不得因为词典不包含新项目就整份拒绝导入**；未经确认不得自动纳入标准词典或污染已确认模板。
8. 词典按检测类型扩展，**不要假设固定最大指标数**；每个新增指标都须核查真实医学身份，不只是添加近义名称。

## 2026-10-16 词典精准定位补充约束
- **必须精准定位，不允许“相似医学术语/近似 LOINC 编码”被当作确认通过**。LOINC 如有不同测量属性（质量浓度/物质浓度、活性/质量浓度）、计算法/直接法或 FEU/DDU，必须精确区分；不能靠同名、单位可换算或别名类似擅自绑定。
- **尿素与尿素氮**：测量对象相关，但一个是尿素整体、一个是尿素中的氮对应计量；原报告身份、数值、原单位保留。不能将尿素氮结果直接作为尿素浓度；**词典身份识别和自动归类时禁止尿素/尿素氮跨身份换算或合并；不需要、也不应以换算作为两者对齐的规划。**
- **LDL-C 直接法与计算法**：同一类胆固醇测量对象，结果取得方式不同；精确 LOINC 映射需按测量属性和方式定位，来源无明示时不能猜；医院只是来源标签。
- **CK-MB**：酶活性浓度与质量浓度分别判别，不能只绑定一个模糊 CKMB 测量术语。
- **D-二聚体**：FEU 与 DDU 必须区分，不可按相同数字视作同一量，不可自行套一个固定比例重写历史值。
- **核验状态严格区分**：“精准匹配并有官方来源”“只有条件候选”“未找到可靠对应”三种。后两种不得计作已精确核验。院方/机器认证不属于任务。

### 2026-10-16 最新明确纠正：身份优先于单位
- **先看完整中文名称和医学含义是否已经区分不同测量身份**；若已明确不同（如尿素 vs 尿素氮），直接保留独立身份，**不讨论通过换算将两者合并**。
- 单位只是辅助身份核对：尤其在名称被省略、CV/SD 被隐藏、文字识别残缺等真正有歧义的情况下用于提示人工核对；不是自动给不同医学指标建立换算关系的依据。
- 此前“尿素氮可换算成尿素”的身份建议作废；仓库 `UnitNormalizer` 不再对 `UREA + mg/dL` 猜作尿素氮并转换为 mmol/L。旧报告不修改。

### 2026-10-16 再次确认：报告只做原文提取，不推导新检验项目
- 用户给出检验报告照片后，助手仅**逐项提取报告上实际列出的检验项目、数值、单位、参考范围、检查日期和医院**，整理成已锁定的粘贴导入格式；不能根据其他项目自行算出一个新项目。
- **未测项目不生成**：不得用总胆固醇、HDL-C、甘油三酯推导 LDL-C，亦不得推算报告没有展示的比值或任何指标；只有报告明确列出的计算型结果才能作为原报告的一项直接录入。
- **不同指标不可跨身份换算**，例如尿素与尿素氮即使存在化学关系也不互转、不合并。
- 单位换算仅在**已确认是同一指标**且确有需求、转换可靠时允许；结果和参考范围上下限需保持一致换算，并保存报告原始数值、单位与精度。通常直接使用报告单位，不因外部 LOINC 的常用单位而修改它。
- LOINC “直接法/计算法”是外部术语精细区分所需的描述，**不是为 HealthTrend 开发计算功能的指令**。当前业务是记录，不是通过算法生成化验结果。


## 2026-10-16 最新规则：缺证据的指标冻结，发现新报告项目时提醒
1. 对**既没有可靠官方医学定义/身份依据、也没有在用户已确认历史检验记录中出现过对应信息**的项目，暂时**冻结扩充、自动映射及推测核验**。冻结表示保留现有词典条目与待核验状态，不删除代码、历史数据或模板，也不将其冒充已通过医学核验。
2. 用户以后发送检验报告照片时，先按原报告逐项提取实际检测项目、名称、代码、结果、单位、参考范围，再与**当前已确认统一指标池及用户已有确认历史项目**比对。医院仅作为提取后报告的来源标签，**不参与指标身份认定**。
3. 如果报告中发现**此前没有确认过的新医学指标**，主动清晰提醒用户“本次报告发现新指标：……”，同时说明来源名称/代码/单位；先标记待核对，由用户确认后决定是否作为新身份或可信别名加入词典。绝不因为一项新增而丢弃整份报告。
4. 如果只是已知指标的**新别名或不同单位表达**，不要误报成新指标；先核实医学含义和单位属性，无法确定时提醒“身份待核对”，不要擅自合并。尤其严格区分 CV/SD、绝对计数/百分比、尿素/尿素氮、PCT/PCTIN、比值方向。
5. **不要推算报告上不存在的项目**；未测不生成，真实来源数据和精度原样保留。用户在聊天中发照片时也执行这条规则，不必等 App 代码支持。
6. 只在用户提供**新的报告项目证据**或发现可核实的权威医学来源后重新启动该冻结条目的核验。无需为所有未使用条目持续搜索、也无需为达到 112/112 编造映射；汇报时分开记录“冻结待新证据”和“待身份确认”。

## 2026-10-16 最新确认：参考范围也放进统一指标池
- **一个医学指标身份（一个 ID）在统一池中允许关联多组不同参考范围**。不同医院同一指标的不同参考上下限都需要保存在该指标池内，不能把其中一组当作固定/唯一/默认正常范围覆盖其他组。
- 每组范围附带报告来源医院、检查类型、原始单位及上下限、出现记录/时间等来源信息；**医院只是范围来源标签，不是指标身份键**。即使不同医院的范围数值相同，来源记录也不能被抹掉。
- 导入新报告时，结果的参考范围以**该次原报告**为准，保留原始值、精度、单位和上下限，并把有效范围作为该指标的又一条有来源的范围证据积累到池中；不把池中其它医院的范围自动填充到本次报告，更不据此推算新检验结果。
- 池内多个范围用于历史溯源和同一指标随时间的区间展示，不是推断所有人通用的参考值。若确需同一身份内部单位标准化，应同时换算上下限，且原始报告值不动。
