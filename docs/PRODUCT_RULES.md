# HealthTrend 产品总规则

> 状态：产品级唯一入口（持续更新）  
> 最近更新：2026-11-07  
> 适用范围：HealthTrend Android App 的需求、交互、数据、兼容、测试和发布

## 1. 使用与维护方式

- 开始任何开发前，先完整阅读本文件，再按本文件链接阅读对应专项规则。
- 用户新确认的需求必须在同一次代码变更中同步更新本文件；不能只留在聊天、提交说明或临时交接中。
- 发生冲突时，优先级为：用户最新明确确认 > 本文件 > 专项规则 > 历史交接/旧实现。
- 旧规则被新规则替代时，要明确标记替代关系，禁止仓库同时保留两套互相矛盾的“现行规则”。
- 不因新增功能破坏旧记录、图片、备份、搜索、趋势、提醒或一键更新。
- 未得到用户明确“发布”指令，不修改正式发布状态，不发布 APK。

- 功能修改如需连带改变已确认的布局、设置或交互，须先说明影响并取得用户同意。

## 2. 产品目标与导航

- 核心链路：报告导入（文本/图片）→ 人工核对 → 保存 → 趋势 → 病程记录 → 图片资料 → 备份/更新。
- 底部导航保持现有正式版本结构；新增能力优先进入所属页面，不增加没有必要的中转页。
- 页面返回后尽量恢复原筛选、滚动和查看位置；弹窗关闭不得把页面送回顶部。
- 首页只保留核心导入入口；检查更新必须直达一键更新，不增加下载中转页。

## 3. 全局 UI 与输入规则

- 全 App 禁止业务线框组件：不得出现描边输入框、焦点描边、底部指示线或文字压线。
- 业务输入统一复用 `AppInputField` 系列；按钮使用纯色/色块设计，标题和按钮按现有系统对齐。
- 禁止为了局部修复擅自改变已确认的色块高度、字号、卡片宽度或页面间距。
- 所有日期和时间使用选择器，禁止手工输入。
- 文字必须完整显示；裁切、遮挡、错误省略属于验收失败。确需单行省略的既有位置必须有明确交互目的。
- 详细 UI 约束见 [`UI_DESIGN_SPEC.md`](UI_DESIGN_SPEC.md)，源码守卫见 `ci/check_ui_design_rules.py`。

## 4. 报告导入、模板与指标

- 同一医院 + 同一报告类型仅保留一个确认模板；OCR 只填检测日期和结果，固定字段来自确认模板。
- 历史模板不参与当前匹配；不得用 OCR 乱码创建新指标。
- 指标匹配综合中文名、代码、顺序、位置和结果类型；结果与参考范围必须分离。
- 原报告单位和显示精度必须保留；可换算值只用于趋势比较，不能改写原报告证据。
- 定性结果保留“阴性/阳性/弱阳/可疑”等文字；血型四项使用独立卡片。
- 数据导出和粘贴格式见 [`DATA_EXPORT_RULES.md`](DATA_EXPORT_RULES.md)。
- 指标身份、别名和医学审计见 [`METRIC_IDENTITY_AUDIT_RULES.md`](METRIC_IDENTITY_AUDIT_RULES.md) 与 [`UNIFIED_METRIC_MEDICAL_AUDIT.md`](UNIFIED_METRIC_MEDICAL_AUDIT.md)。

## 5. 趋势规则

- 单位相同或可可靠换算的数据允许连接；不可换算时必须断开。
- 医院颜色在卡片、点位和整体趋势中保持一致；曲线平滑但不得改变真实点位。
- 整体趋势不显示普通数据点，必须完整显示全局并保持卡片居中、四边留白；横屏模式不滚动。
- 化疗和升白针属于独立事件层，不插入检验时间槽，不制造曲线断点。
- 化疗三角、升白针圆点及其竖线使用已确认的统一颜色，仅靠形状区分。
- 参考范围与趋势细则见 [`TREND_REFERENCE_RULES_2026-10-23.md`](TREND_REFERENCE_RULES_2026-10-23.md)。

## 6. 病程记录总规则

- 病程进程总控包含外照、观察、后装、结疗复查。化疗天数独立开关，外照计划默认 27 次、后装计划默认 5 次。外照达到计划数后停止，调高计划并重新开启时从历史最大次数继续。总控只影响以后生成的新卡，不回算或改写历史卡。
- 手动把当天标题改为“3化1”即建立第三次化疗起点；若同日外照可写“3化1-放N”。后续新卡从这个标题继续计算。编辑其他内容不得触发标题或标签变化。
- 病程分类新增可选「复查」，在现有分类末尾一次性补充。已有同名分类沿用，删除后不再补回。选择复查保留当前标题，升级不修改历史卡。

- 病程卡首行的星期、日期、标题、针头和阶段标签垂直居中。点击类目后，按整个模块的实际上下边界居中，包含标题、输入、按钮及已添加的图片，到达滚动边界即停止。港维护每行显示“冲N、日期、天数”，首次从安港日算起，以后从上次冲管日算起，安港入口显示“安港”。

- 旧空卡不套用当前模板，自动补齐过去日期时保留空白；当日新卡使用建卡时的模板，历史手填内容继续保留。

- 病程编辑在内容变化后自动保存。关闭、返回、切到后台时处理最后一次输入；病程编辑页移除底部保存按钮和占位；自动保存成功后顶部短暂提示，写入失败时顶部显示“保存失败”和“重试”，保留当前输入。日期未选或体重等输入尚未填写完整时保存编辑草稿，重开可续填。

- 自动创建病程卡时保存当时各板块的默认模板，卡片首屏与编辑页共用文本；模板预填不算人工记录。日期名称行从头编辑，阶段、升白针、血压、体重及文字板块的图标和内容定位至对应编辑位置。图片保留预览，体重箭头保留趋势入口。

- 病程页港维护横条左侧的历史图标打开记录卡。安港和冲管分别保存，日期通过选择器补录或更正；按实际日期编号，首次距安港、以后距上次冲管按自然日计算。点击“已维护”登记当天，同日重复点击仅保留一次；旧版单独保存的日期在确认类型前单独展示。

- 下次港维护日期从左侧维护日期起算 28 个自然日；第 28 天为周六或周日时，提前到同一周的周五。点击“已维护”时记录手机当天日期，并据此重算下次日期；手动选日期用于补记或纠错。

- 每个自然日最多一张病程卡；重复日期直接打开已有空卡，已有内容时提示并禁止重复新增。
- 系统可自动补齐日期卡；放疗编号跳过未放疗日，化疗连续多日只把第一天视为新一化起点。
- 分类 key 必须稳定；重命名只改显示名称，不改历史数据、颜色、排序或自动编号逻辑。
- 升白针使用明确布尔字段记录，不能继续从新备注猜测；趋势连续段只取首日，病程筛选显示每个明确标记日。
- 血压、脉搏、体重、BMI、体表面积、港维护、提醒等现有规则不得被通用板块改造覆盖。
- 固定内容板块当前包括症状、检查、治疗、药品/取药、饮食、备注；均支持文字和图片（相册/拍照），旧记录缺字段时读为空。

## 7. 病程文字模板（2026-11-01 新确认）

### 7.1 模板与历史记忆分离

- “历史输入建议”是系统从既往输入自动形成的联想列表；“文字模板”是用户主动保存和管理的固定内容，两者必须使用不同的数据源和 UI 状态。
- 每个文字板块拥有独立模板列表，不能把饮食模板混入备注、治疗等板块。
- 模板只保存文字，不保存当天图片或当天实际内容。

### 7.2 默认模板

- 用户选择一次模板后，该模板成为该板块的默认模板；以后新建病程卡时自动填入，无需每天重新选择。
- 例如饮食默认模板可为：`早：\n午：\n晚：`。
- 当天对预填文字的编辑只影响当天记录，不反向修改模板。
- 编辑已有记录时，以该日已经保存的内容为准，模板不得覆盖。
- 只有用户主动切换默认模板、编辑当前模板或删除当前模板，后续预填内容才改变。
- 删除当前默认模板后，该板块恢复无默认模板，或由用户明确选择另一个模板；禁止静默改用随机模板。

### 7.3 模板入口与管理

- 模板按钮位于对应板块标题行最右侧，不增加中转页面。
- 点击后可查看已存模板、立即套用、设为默认、重命名、编辑和删除，并可把当前输入另存为模板。
- 手动套用模板到已有非空内容前必须防止无提示覆盖；采用明确替换确认或只填充空输入。

## 8. 用户自定义病程板块（2026-11-01 新确认）

### 8.1 能力范围

- 病程编辑页提供“添加板块”入口，用户无需改代码即可增加完整模块。
- 一个自定义板块固定包含：标题行、文字输入框、清空入口、模板入口、相册添加图片、直接拍照和缩略图管理。
- 新板块保存为全局板块定义，之后的新病程编辑页继续显示；当天文字和图片仍按日期分别保存。
- 支持修改标题、排序、隐藏/恢复。若已有历史内容，“删除”只能转为隐藏，不能删除历史内容或图片关联。

### 8.2 数据结构约束

- 禁止再为每个新板块向 `CourseRecord` 添加一对固定的 `xxxText/xxxImages` 字段。
- 使用稳定 `sectionId` 的“板块定义”与按 `sectionId` 保存的“每日板块内容”分离结构。
- 重命名只改板块显示标题，稳定 `sectionId` 和历史内容不变。
- 模板必须绑定稳定 `sectionId`，不能绑定可变标题。
- 固定板块可继续兼容现有字段，但 UI、模板和图片行为应通过同一板块描述层统一，避免两套交互继续分叉。

### 8.3 必须同步覆盖的链路

- 保存/读取与旧 JSON 兼容。
- 备份导出、恢复与“是否有受保护配置”判断。
- 病程搜索、空白卡判断、卡片展示顺序。
- 图片查看、替换、追加、排序、移除和删除确认。
- 编辑草稿恢复、屏幕旋转/进程恢复。
- 隐藏板块的历史内容仍可恢复查看。
- 针对模板默认值、已有记录不覆盖、重命名不丢数据、隐藏不删历史、备份往返增加回归测试。

## 9. 病程模板/自定义板块与现有功能的冲突处理

- 不复用医院检验报告模板表，避免“报告模板”和“病程文字模板”概念及存储相互污染。
- 不复用历史输入建议列表，避免选择一次后被后续历史排序替换。
- 默认模板不能让系统自动补齐的卡片立刻变成“有实际病程内容”；建卡时单独保存模板快照，未编辑时卡片直接显示预填内容。
- 自定义板块定义属于配置，板块每日内容属于病程数据；两者在备份中分别保存。
- 固定板块迁移到通用描述层时必须保留旧字段读取，禁止一次性破坏式迁移。
- 自定义板块不得参与化疗/放疗编号、阶段分类、升白针事件或提醒判定，除非以后有新的明确规则。

## 10. 图片资料

- 图片支持缩略图导航、放大缩放、前后切换、替换、追加、排序、删除确认和失败重试。
- 图片移除默认只解除当前记录关联；不得误删其他记录仍在使用的原图。
- 返回时恢复原图片和原列表位置。

## 11. 提醒与后台通知

- 后装提醒选择“第几次”和日期后，当天病程卡自动显示“后装N”标题及后装标签。复查提醒当天自动显示复查标题及标签。改期时标题和标签一起移到新日期，用户无需再编辑卡片；自己填写的内容不受影响。

- 提醒类型增加后装和复查，按选定日期时间提醒。后装显示第几次，复查填写项目。提醒独立保存，操作提醒不改历史卡或治疗计数。

- 每条治疗提醒可选稍后 1 小时、次日当地时间 09:00 或已完成。点返回或弹窗外按稍后 1 小时处理。推迟截止时间随提醒保存，重新打开、切到前台及系统通知均遵守同一截止时间。

- 病程页右上角“+”用于添加提醒；提醒支持放疗次数和普通日期时间。
- App 关闭后使用系统通知；不以后台常驻或高频轮询实现。
- 所有保存、完成、恢复和删除经 `HealthStore` 同步系统任务。
- 旧的病程“检查提醒”仅保留兼容字段，不恢复入口。

## 12. 数据安全、兼容与备份

- 新功能须覆盖旧格式记录升级读取、修改单项并重新打开的回归检查。历史卡编辑无关字段时，原有标题和阶段按已保存值保留。使用旧格式、多日期、有图片的合成记录验证保存并重新打开后的字段。

- 新字段必须提供旧数据默认值；读取旧 JSON 不崩溃、不改写无关字段。
- 所有用户可配置内容都必须进入备份；恢复前的保护判断必须覆盖新增配置和新增病程内容。
- 改名使用稳定身份，不批量重写历史记录。
- 删除配置前先判断是否被历史数据引用；有引用时只隐藏。
- 任何可能丢失病程文字、图片、报告原图、模板或指标规则的迁移都必须停止并取得用户明确确认。

## 13. 测试与发布

- 小改优先运行受影响的聚焦测试和同步守卫，不为排版小改盲目跑全套 CI。
- 持久化改动至少覆盖：新旧 JSON 往返、备份恢复、搜索、空卡判断和进程恢复。
- 图片改动覆盖所有图片类型的查看、替换、追加、排序和移除。
- 发布前必须确认版本号、更新入口、原签名证书和 APK 功能完整；签名不一致不得发布。
- 失败先读取真实日志定位；连续两次仍未解决时停止盲改，说明根因和回退方案。
- 开发流程和检查项见 [`DEVELOPMENT_CHECKLIST.md`](DEVELOPMENT_CHECKLIST.md)、[`CHANGE_SYNC_POLICY.md`](CHANGE_SYNC_POLICY.md) 与 [`AI_HANDOFF.md`](AI_HANDOFF.md)。
